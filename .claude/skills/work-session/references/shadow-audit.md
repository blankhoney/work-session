# Immutable Shadow audit through Quality Manager

Construction is primary. Immutable Shadows are fresh read-only advisory children managed only by the single session-long Quality Manager. Their source mirrors and exact launch adapter remain byte-identical. Lead never schedules a Shadow, pairs them, observes child chatter, or creates another candidate-bound quality orchestrator.

## Independent module triggers

A completed module may trigger each Shadow at most once for its current frozen candidate:

- **Architecture Shadow** only when current code changes a module boundary, stable interface, dependency direction, or production integration.
- **Task-contract Shadow** only when current code changes acceptance behavior, frozen behavior, a domain invariant, or a required end state.

Do not launch them automatically as a pair. A module must first satisfy the module completion facts in `quality.md`; its Conformance and module relation review are separate. Construction repair does not reopen or repeat either Shadow. Test/helper/final-harness/format/comment/internal rename/generated-sync/ordinary-failure work does not create a Shadow trigger unless it materially changes one of the exact trigger facts above.

Docs, checklists, reports, evidence wording, hashes, diagrams, screenshots, Task phase, and owner wording never create an audit candidate.

## Fresh launch envelope

Read `agents.md`, exact `launch.md`, and only the independently triggered byte-identical source:

- `references/shadows/architecture-review.md`; or
- `references/shadows/task-contract.md`.

The Manager launches a fresh generic one-shot child, never a fork, using the exact adapter. The sanitized prompt-only trajectory contains only:

```text
WorkRoot: <absolute authorized root>
PrimaryPaths: <principal owner-released paths>
Candidate: <real identity or current source baseline>
Contracts: <relevant frozen MUST ACCEPT and ARCH MUST locators>
Requested: <one trigger-specific result>
NativeChecks: <existing relevant targeted entries>
Output: <source-defined schema/template>
Stale: candidate/path drift => STALE
```

No Main transcript, prior report, private reasoning, worker chat, decision history, construction narration, or extra audit criteria. Bounded WorkRoot autonomy and capacity are defined once in `quality.md`. The exact Shadow source remains responsible for its method and output; the envelope only supplies current facts and the authorized root. A Shadow cannot spawn a child.

## Transport and buffering

Audit state is transport only and never product progress. Child ACK/active/idle, individual findings, clean results, unavailable results, duplicates, and stale results stay inside the Manager buffer. Timeout/crash is terminal unavailable; stale closes silently; there is no automatic repeated launch. A clean Shadow result is advisory-not-acceptance.

The Manager sends Lead no Shadow-specific chatter. Any Shadow root cause remains advisory and can reach Lead only through the bounded digest. The Manager preserves exact locators and root cause but cannot make a Shadow result block, trigger repair, change Task/phase/status/acceptance, dispatch construction, edit interfaces/behavior/architecture/dependencies, ask the user, invoke Attention, commit, push, or broaden scope.
